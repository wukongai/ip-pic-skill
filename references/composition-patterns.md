# 构图模式与原创隐喻

派生自 Ian Xiaohei Illustrations 的 8 类结构。每张只选一种主结构，不混成复杂信息图。

## 结构类型

### Workflow 流程

输入 → 处理 → 输出。人物在中间操作装置，橙色只标主流向。

### 系统局部

只画 3–5 个核心模块。人物可用中景或大半身参与一个关键动作，不强制缩小。

### 前后对比

左混乱、右稳定，或上旧状态、下新状态。人物可以搬运、修补或转动中间机关。

### 角色状态

2–4 个小状态或小漫画格。适合焦虑、卡住、协作、整理和前后变化。

### 概念隐喻

一个有记忆点的具象物件组合，少量输入，一个输出。人物与装置共同完成关键动作。允许天平、轨道、连接器等精致物理结构，但不能默认做成工厂机器。

### 方法分层

用抽屉、台阶、货架、盒层或工作台表达层级；人物搬砖、搭建、标记或巡检。

### 地图路线

一条弯曲路径与少量节点。人物牵线、扶梯、过桥、守门或修路。

### 小漫画分镜

2–4 个小场景，每格一个动作。用于打破连续单人站姿并表现变化过程。

## 原创隐喻三步法

1. 抽象概念转成物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 系统结构优先转成熟悉且与主题直接相关的物件：秤、餐盘、日历、书、桥、磁扣、容器、票据、线团、抽屉、地图、门、路径；只有原文确实讨论生产系统时才使用机器、管线或传送带。
3. 让人物承担动作：拉、扛、塞、捞、压、称、缝、剪、拧、守、推、接、拆、标记、回收。

每张只保留 1 个主隐喻系统；系统可由 2–5 个熟悉物件组成，但必须由一个动作或一条路径统一，不能变成并列图标清单。物件、动作和构图必须为当前内容重新发明。

## METAPHOR-001 · 具象精致而非工业／UI 泛化

- 先写出“观众看到什么物件就能猜到主题”，再写人物动作；不能先套机器或透明面板再寻找解释。
- 允许精致金属、象牙白石材、半透明蓝色树脂和纸张等触感，但所有材质必须插画化，不能滑向 3D 产品渲染。
- 主体对象优先占画面 38%–58%，人物以动作进入；主题需要闭环时使用一条橙色主路径和至多一条蓝色次路径。
- `two-step-publish` 和视频的物件短标签由确定性文字层处理；`direct-integrated` 可一次生成少量短标签。无论哪种模式，场景本身都不能依赖长段文字才能看懂。

## 六种方屏构图轮换

1. `diagonal-cross`：人物斜向跨画面操作主物件。
2. `top-down-partial`：俯视桌面，人物只露侧脸、背影或双手。
3. `seated-loop`：坐姿与圆形闭环共同构图。
4. `close-hands`：手部近景穿过画面，物件为主角。
5. `object-dominant`：主题装置占主导，IP 只以局部或小中景参与。
6. `contrast-bridge`：人物跨越或连接左右两种状态。

相邻镜头不得重复构图家族；连续三张至少覆盖三种人物裁切方式。禁止连续使用“左上标题 + 右侧全身人物 + 下方桌面装置”。

## 视频构图轮换

为连续视频分镜记录以下字段：

- `structure_type`
- `shot_type`: editorial-hero / concept-partner / data-evidence / contrast-split / workflow-stage / seated-analysis / close-up-detail
- `ip_scale`: brand-hero / co-lead / analysis-medium / close-up
- `orientation`: front / left / right / back-three-quarter
- `action`
- `visual_anchor_position`: left / center / right
- `motion_hint`: push-in / pan-left / pan-right / crop-detail

生成下一镜前检查最近两镜，不重复同一组合。

## 反复刻

上游示例只校准留白、线条、颜色与角色参与方式。不得直接复用传送带断点、素材鱼、内容机器、信息井、信任桥等案例的物件组合和空间拓扑。
