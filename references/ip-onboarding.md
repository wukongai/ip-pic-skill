# IP Onboarding

首次使用只收集影响身份一致性和授权的字段。一次问一个关键问题，不要求用户理解 schema，也不要求用户配置图片接口。

## 进入条件

按顺序寻找：

1. 用户在本次请求中明确提供的角色资料、附件或路径；
2. 当前项目 `.custom-ip-illustration/ip-profile.json`。

都不存在时才进入 onboarding。不要搜索其他私人目录，不要自动复制仓库示例。

## 第一问

先解释：“角色一致性配图需要一份你有权使用的角色资料。我可以带你跑虚构人物教程，或一步步建立你自己的角色。”

然后一次只问这个选择：

- **教程**：使用仓库原创虚构人物 Mira 体验流程；
- **我的角色**：建立用户自有、获授权或有许可证的角色。

选择教程时：

- 明确 Mira 只用于本次教程，不是用户角色，也不是默认身份；
- 读取 `examples/ip-profile.example.json` 与 `examples/brief.example.json`；
- `examples/demo-character.svg` 只用于向用户预览人物；
- 不把示例 profile 写入用户项目；
- 默认先 compile-only，除非用户已明确要求生成图片。

## 建立自己的角色

严格一次问一个问题。用户已经回答过的字段不要重复问。

## 必填

1. `ownership.status`
   - `user_owned`：用户本人创作并拥有。
   - `licensed`：通过许可证获得使用权。
   - `authorized`：权利人明确授权。
2. `ownership.basis`：一句话说明权利来源，不需要上传合同。
3. `identity`：角色名称和一句身份描述。
4. `appearance`：整体外观和至少一个签名特征。
5. `personality.traits`：影响动作和表情的性格词。
6. `continuity_anchors`：跨图不可漂移的轮廓、配色、服装或道具。

推荐提问顺序：

1. “这个角色是你原创拥有、已获授权，还是通过许可证使用？请用一句话说明来源。”
2. “角色叫什么？用一句话介绍身份。”
3. “人物整体长什么样？最容易认出的特征是什么？”
4. “用 2～4 个词描述性格，这会影响动作和表情。”
5. “哪些外观、服装、颜色或道具在不同图片里绝不能变化？”
6. “是否有本次允许使用的参考图？没有也可以。”

## 参考图

- 只登记用户允许本次工作使用的图片。
- 每张写明 `purpose` 和 `authorized: true`。
- 授权素材库存不等于每张图都要使用；编译器只挑选身份、外观和风格所需素材。
- 参考路径只进入 render request，不进入 prompt 正文。

## 预览与保存

字段齐全后，先展示人类可读摘要：

- 权利状态与来源；
- 名称与身份；
- 外观和签名特征；
- 性格；
- 连续性锚点；
- 已授权参考图数量；
- 拟保存位置 `.custom-ip-illustration/ip-profile.json`。

同时提醒：该文件是明文 JSON，可能被 Git 或云盘同步；若含不适合同步的外观、权利依据或本地路径，建议把 `.custom-ip-illustration/` 加入用户项目的 `.gitignore`，或本次只保留在对话中。

询问用户是否确认保存。未确认时只保留在当前对话，不写文件。文件已存在时，先说明将覆盖并再次确认。角色资料不得包含凭证、provider、模型、服务地址或与角色无关的私人知识库内容。

保存后再询问内容、图片数量、画幅、输出目录，以及“只编译”还是“生成图片”。后端保持 `auto`，除非用户主动指定。

## 停止

- 用户不知道角色权利来源。
- 用户明确要求模仿一个不属于自己的受保护角色。
- 身份一致性依赖的参考图不可访问。
