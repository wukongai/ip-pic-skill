# IP Pic 傻瓜式用户手册设计

日期：2026-08-02
状态：已批准，待实现
适用版本：`0.3.0-rc.2` 后续本地候选

## 1. 目标

让第一次接触 `ip-pic` 的用户只按手册逐步操作，就能完成：

1. 安装前检查与进入 Skill 根目录。
2. 验证安装与运行自动化测试。
3. 准备自有或已授权的 IP 形象素材。
4. 编译文章 IP 配图或静态视频关键帧。
5. 按所选后端完成渲染交接。
6. 完成 `direct-integrated` 或 `two-step-publish` 的文字流程。
7. 逐图 QA、失败重做和整批重建。
8. 在不破坏官方等价版本的前提下，调整内置风格或创建个人 fork 风格。
9. 出错后根据症状定位原因并安全回退。

## 2. 设计原则

### 2.1 手册必须与真实接口一致

每条命令都必须满足以下条件：

- 可复制执行，不引用不存在的脚本。
- 明确当前目录、输入文件、输出目录和预期产物。
- 明确成功标志和失败后的下一步。
- 不假设用户了解 JSON、终端、字体文件或后端配置。
- 不把结构测试写成真实视觉验收。

### 2.2 两类定制必须分开

#### 官方等价版本内的安全定制

用户可以：

- 在一次任务中选择六种内置渲染风格之一。
- 使用自有或已授权的角色素材。
- 调整 brief 中的内容、比例、构图和交付模式。
- 在 `two-step-publish` 后处理阶段指定本机字体。

这些操作不修改 Skill 本体，仍属于官方等价运行。

#### 个人 fork 定制

用户可以在复制出的个人 fork 中：

- 修改已有风格参数。
- 新增第七种或更多渲染风格。
- 新增标题带或静态视频文字样式。

这类操作会离开官方“固定六风格、原版等价”发行合同。手册必须说明备份、校验、测试和回退方法，不得宣称修改后的 fork 仍是官方等价发行物。

### 2.3 两种文字模式不得混淆

- `direct-integrated`：文字与画面由图像模型一次性融合。手册不承诺本地字体文件能控制模型生成的字体，只要求按原版粗手写标题、强调线等提示与 QA 规则执行。
- `two-step-publish`：先生成不含最终文字的底图，再由确定性文字层合成标题。手册提供可执行的合成命令，允许用户在输出目录中传入有合法使用权的本机字体。

### 2.4 文章与视频风格接口必须如实描述

- 文章配图通过 `selection_receipt.style_variant_id` 选择六种内置风格。
- 静态视频关键帧通过视频模板选择既有结构与风格；当前视频编译器不读取文章选择回执。
- 新增视频风格属于维护者开发或个人 fork，不伪装成文章风格的同一配置入口。

## 3. 交付物

### 3.1 公开发行内

- `USER-GUIDE.zh-CN.md`：简体中文主手册。
- `USER-GUIDE.en.md`：行为一致的英文手册。
- `references/customization.md`：官方定制边界与个人 fork 教程。
- `scripts/compose_publish_layout.py`：`two-step-publish` 确定性文字层命令行入口。
- 可直接复制的文章与视频示例。
- 修正后的 `skill.contract.yaml`，只声明真实存在的脚本和真实输出。

### 3.2 项目测试目录外部

- `START-HERE-USER-MANUAL-TEST.md`：绑定项目级测试副本绝对路径的人工 E2E 起点。
- Agent 用户模拟记录与评分。
- 仍需用户人工判断的真实视觉验收清单。

公开发行文档不得写入作者私有绝对路径。

## 4. 验收标准

### 4.1 自动化

- 文档中引用的本地脚本、示例和参考文件全部存在。
- `two-step-publish` 可从 `run-manifest.json` 提取布局并合成最终图。
- 用户显式指定普通字体文件时使用字体第 0 个 face，避免沿用内置 TTC 索引造成失败。
- 显式提供的角色 profile 会经过公开 ownership/结构校验。
- `skill.contract.yaml` 不再声明不存在的入口或独立 selection receipt 文件。
- 私人身份、路径、凭证和私有业务信息扫描通过。
- 原版能力映射、13 个结构模板、六风格合同和全部既有测试继续通过。

### 4.2 用户模拟

一个未参与实现的 Agent 只能阅读公开手册并完成以下任务：

1. 找到起点并验证安装。
2. 完成无付费 API 的 `prompt-only` 文章流程。
3. 解释如何换成自有角色素材。
4. 解释两种文字模式的区别。
5. 找到 `two-step-publish` 的真实合成命令。
6. 正确说明文章与视频的风格选择差异。
7. 正确判断“修改内置风格”和“新增第七风格”是否仍为官方等价版本。
8. 找到 QA、重做、批量重建和回退步骤。

模拟评分目标不低于 90/100；任何阻断执行的问题必须修正后重新模拟。

## 5. 非目标

- 不修改原版 Image Factory 私有工作流。
- 不把个人角色、私有素材或本机字体打包进公开 Skill。
- 不新增第二个竞争 Skill 名称。
- 不在本轮 push、tag、发布 GitHub Release 或修改 Global Skill。
- 不用文档掩盖当前不支持的接口。
