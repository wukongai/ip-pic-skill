# IP Pic 发布级真实 E2E 与用户交付证据设计

## 目标

在独立测试项目中，完全按普通用户手册模拟内容创作者使用 Agent 的过程，对公开版 `ip-pic` 完成可重复、可审计的真实效果测试，并形成用户可理解的手册、截图、视觉画廊、机器回执和发布结论。

本轮不是用静态检查替代视觉验证。真实图片必须由图片工具生成，准备好的原创教程角色“学习向导阿拓”参考图必须实际进入渲染请求，所有视觉结论必须由独立 QA Agent 逐图检查。

## 边界

- 原版 Image Factory 只读，不修改、不切换、不把公开候选接回原版工作流。
- 所有改动只发生在隔离候选和专用 `test-table/ip-pic-e2e` 测试项目。
- 不修改 Global Skill。
- 不 push、不 tag、不创建 GitHub Release。
- 不读取、复制或记录任何私有凭证、provider、adapter、余额、fallback 或内部路由配置。
- 用户私人身份、外貌、服装、饰品、角色资料、业务路径和品牌信息不得进入公开候选或测试报告。
- 对外仍使用 `ip-pic` / “IP 配图”。

## 发行结论的证据层级

报告必须分开陈述：

1. **结构与安全门禁**：测试、Doctor、Skill Up、Waza、许可证、隐私扫描。
2. **真实任务效用**：同一份公开 Skill 在全新用户项目中的真实图片结果。
3. **视觉 QA**：逐图检查角色连续性、中文、构图、动作、表情、视线、姿态、文字安全区和风格差异。
4. **环境覆盖限制**：哪些宿主和后端真实运行，哪些只完成合同验证或安全失败关闭。

没有真实图片或真实回执的路径不得写成“真实通过”。Agent 视觉评审不得伪装成作者本人已人工签字。

## 隔离测试架构

建立一个新的发布候选测试运行目录：

```text
test-table/ip-pic-e2e/runs/2026-08-03-release-grade/
├── clean-user-project/
│   ├── .agents/skills/ip-pic/
│   ├── article/
│   ├── character-assets/
│   └── personal-styles/
├── inputs/
├── cases/
├── outputs/
├── receipts/
├── screenshots/
├── qa/
├── logs/
├── matrix.json
├── VISUAL-GALLERY.md
└── REPORT.zh-CN.md
```

`clean-user-project` 不读取 Image Factory 源码，也不读取历史输出。公开 Skill 从当前隔离候选复制到项目级 `.agents/skills/ip-pic`。阿拓参考图保存在 Skill 外部的 `character-assets/`，以 `user-owned-or-authorized` 身份登记。

## 用户模拟

测试采用三个相互独立的角色：

1. **新手用户 Agent**：只读取普通用户手册和项目级 Skill，从手册第一步开始执行，不接受维护者内部说明。
2. **视觉 QA Agent**：只读取真实输出、公开角色资料、case 验收标准和回执，不修改图片。
3. **发布审计 Agent**：检查证据链、隐私、路径、后端声明和公开文案是否与真实运行一致。

主 Agent 负责确定性脚本、真实图片工具调用、Computer Use 截图和最终交叉核验。任何 reviewer 报告都必须由主 Agent用文件、hash、测试输出和实际图片复核。

## 真实视觉覆盖矩阵

真实图片调用上限为 24 次，包括失败重做。最终有效样本至少覆盖全部 13 个正式结构，并在同一批样本中交叉覆盖 6 个原版渲染风格。

| 能力 | 最低真实覆盖 |
|---|---:|
| 正式结构模板 | 13 / 13 |
| 渲染风格 | 6 / 6 |
| 画幅 | 16:9、1:1、3:4、9:16 |
| direct-integrated | 至少 3 张，必须出现可读中文和单条手绘强调线 |
| two-step-publish | 至少 2 张，保留无字 raw 并确定性加入文字 |
| 静态视频关键帧 | 1:1 与 9:16 各 1 张 |
| 长文章连续批次 | 同一篇文章 5 张 |
| 角色参考图 | 所有身份连续性样本必须实际 handoff |
| 失败恢复 | 至少 1 个定向失败，只重做失败项 |
| 整批重建 | 新目录生成，旧批次不覆盖 |

13 张正式结构样本可以同时承担风格、画幅、交付模式和长文连续性覆盖，不做没有新增证据价值的笛卡尔积重复出图。

## 后端覆盖

- **Codex Image Tool**：必须真实出图、保存文件并完成 receipt。
- **OpenAI Direct**：仅在宿主已安全配置凭证且调用不会暴露凭证时真实运行；否则验证缺凭证失败关闭、官方 endpoint allowlist、参考图编辑请求和脱敏错误。
- **宿主 ai-router**：仅通过公开 MCP 接口检查与调用，不读取私有配置；可用时真实出图，不可用时记录结构化不可用状态。
- **prompt-only**：必须停在 `prompt_ready` / `rendered=false`，不得冒充图片完成。

后端不能改写 director plan、模板、文字策略、prompt、参考图选择、尺寸或 QA 合同。

## 逐图 QA

每张真实图片至少检查：

- 阿拓的脸型、黑色短发、圆角眼镜、芥末色外套、青色内搭和整体年龄气质是否与授权参考图一致；
- 角色是否承担核心动作，而不是角落贴纸；
- 动作、表情、视线、尺度和姿态是否匹配 director plan；
- 构图家族的空间关系是否真实可辨认；
- direct-integrated 是否有少量可读中文、粗重端正主标题和单条手绘强调线；
- two-step raw 是否无字，final 字层是否无裁切、无重叠、未覆盖 raw；
- 视频关键帧是否保留字幕安全区；
- 风格变化是否只改变表现，不改变角色身份、语义或画幅；
- 是否出现水印、logo、假码、占位框、未授权角色或隐私信息。

明显不合格的样本不得通过。优先只重做渲染层；只有证据证明上游合同错误时，才按 TDD 修复最低根因层。

## 用户手册与插图

普通用户手册保持 Agent-first 和示例-first，不加入 Python、JSON 或终端操作。

本轮新增：

- 一张“文章 → Agent → IP Pic → 逐图确认 → 保存到项目”的说明插图；
- 更清晰的开始、日常使用、自定义、文字、失败重做和反馈分区；
- 每个主要模块加入不可见的插图锚点，方便维护者以后换成自己的 IP 配图，不向普通用户展示占位提示；
- “已验证范围”与“问题反馈”说明。

公开说明使用专业事实表达：

> IP Pic 是从一套长期使用的大型内容图像工作流中独立整理出的开源 Skill。当前版本已经完成自动化合同、安全检查和列明环境下的真实图片 E2E。不同 Agent、图片模型版本、API 中转环境和本机字体仍可能产生差异；建议先运行手册中的阿拓示例，并通过项目 Issues 反馈可复现的问题。

不得写成“作者没有时间测试”或声称覆盖了实际未运行的宿主环境。

## 截图与可复验报告

Computer Use 截图至少覆盖：

1. 全新用户项目和项目级 Skill；
2. 用户手册首页与第一次示例；
3. 阿拓参考图和参考图登记证据；
4. direct-integrated 真实输出；
5. two-step raw 与 final；
6. 1:1 / 9:16 视频关键帧；
7. 长文五图画廊；
8. 13 结构 / 6 风格矩阵；
9. 自动化测试与最终报告摘要。

截图旁必须链接原始文件和机器回执。截图不是唯一证据，原始图片、request、receipt、QA JSON、日志和测试输出必须保留。

## 放行门禁

只有同时满足以下条件，报告才可以写“当前列明环境达到发布候选标准”：

- 自动化测试零失败；
- 13 / 13 正式结构、6 / 6 风格有真实图片证据；
- 准备好的阿拓参考图真实进入身份连续性样本；
- direct-integrated、two-step-publish、1:1、9:16 和长文五图均有真实输出；
- 逐图 QA 无 Critical / Important 未解决项；
- 隐私、凭证、路径、许可证和非覆盖门禁通过；
- 手册第一条示例由新手用户 Agent 独立完成；
- 公开说明与真实覆盖一致。

如果图片调用上限耗尽后仍有未通过项，整体状态保持“尚未完成”，报告必须列出失败样本和唯一下一步，不得降低门禁。
