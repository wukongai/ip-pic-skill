# IP Pic 验证说明

这份说明帮助用户区分“功能合同通过”和“某一张图看起来已经满意”。

## 已验证范围

公开候选的自动化验证覆盖：

- 13 个正式 IP 结构模板与 1 个兼容模板；
- 6 种渲染风格；
- 16:9、1:1、3:4、9:16 画布；
- 一次图文融合、先无字图再加标题、静态视频文字层；
- 文章内容规划、逐段认知锚点、人物表情、动作、视线和姿态合同；
- 已授权参考图选择、选择回执、批量连续性、部分失败和只重做失败项；
- Codex Image Tool、OpenAI Direct、宿主 ai-router 和 prompt-only 的边界；
- 隐私、凭证、私人路径、未授权图片、拒绝覆盖与许可证门禁。

真实图片抽样还验证了：同一篇六段文章可以生成六张内容不同、与各段相关的 direct-integrated 图文融合配图；中文主标题、副标题、较粗字形和单条手绘强调线能够真实出现在画面中。表情或视线不符合导演计划时，必须判为需要重做，不能只因文字正确就放行。

## 自动化验证不能保证什么

图片模型具有随机性。不同 Agent、图片模型、字体、系统和参考图会影响：

- 角色脸部与服装的一致程度；
- 指定表情、动作、视线和姿态的执行强度；
- 中文小字的准确度；
- 文字与复杂背景的对比度；
- 方屏或竖屏中的安全留白和裁切。

因此，结构测试通过不等于真实视觉通过。Agent 必须把最终图片给用户看，逐张核对人物、内容关联、文字、安全区和权利来源。

## 第一次使用的安全验收

1. 先运行用户手册中的阿拓短文示例。
2. 确认拿到真实图片，而不是只有提示词。
3. 确认标题为可读中文，并与画面内容一致。
4. 再用一篇自己的短文章测试 2–3 张连续配图。
5. 最后换成自己拥有或已获授权的角色参考图。

任何一步出现问题，都可以让 Agent 保留旧结果，只重做失败项。

## 如何反馈可复现的问题

请提供：

- 输入文章或可公开的最小复现文字；
- 使用的 Agent 和图片工具类型；
- 选择的风格、画幅和文字方式；
- 失败图片；
- 期望效果与实际现象。

不要提供 API Key、token、私有路由配置、无权公开的角色图或含私人身份的信息。
