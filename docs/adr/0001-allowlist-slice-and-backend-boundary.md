# ADR 0001：采用 allowlist 公开切片与不可变渲染边界

## 状态

Accepted，2026-08-01。该决策来自用户已批准的跨版本产品边界。

## 背景

失败候选通过重新设计少量通用模板实现了“看起来相似”的 IP 配图，但丢失了原版结构、文字和导演合同。另一方面，直接复制 Image Factory 会泄露私人身份、品牌资产、私有业务和 ai-router 运行时。

## 备选方案

### A. 继续补丁失败候选

优点是文件少。缺点是其抽象已经把 13 个结构折叠成 8 个，无法证明完整等价；每次发现遗漏都需要追加规则。

### B. 整仓复制后用 denylist 删除

优点是初始行为最接近原版。缺点是私人资产和非 IP 业务默认进入候选，遗漏一次删除就可能泄漏；也难以证明什么被排除。

### C. 从原版依赖图构建 allowlist 公开切片

逐项把原版文件和能力标为 `copy`、`rename`、`sanitize`、`backend-adapt` 或 `exclude`；默认拒绝，任何未映射项阻断发布。后端只消费不可变 handoff。

## 决策

选择 C。

## 结果

- 原版行为可以通过 manifest 和双端 golden 证明。
- 私人身份、非 IP 业务和私有运行时必须显式排除。
- 后端适配可以增加或替换，但不得改变 director、template、prompt、manifest 或 QA。
- 新增原版 IP 文件时，公开版测试会因未映射而失败。
- 发行复杂度高于轻量重写，但这是完整等价和脱敏安全所必需。
