# ADR 0002：采用项目本地、版本化、确认后写入的定制存储

## 状态

Accepted，2026-08-04。

## 背景

IP Pic 的重要产品价值是让普通用户通过 Agent 持续完善自己的角色、参考图、渲染风格和导演习惯。当前单次 brief 可以临时覆盖部分字段，但不能安全复用、版本化或回退。把用户配置写入公开 Skill 安装目录会泄露隐私，并在升级时丢失。

## 备选方案

### A. 让 Agent 直接编辑安装目录

实现最快，但会污染公开 Skill、破坏升级和脱敏边界，也没有一致的校验、版本或回执。

### B. 使用用户级全局配置

可跨项目复用，但默认扩大私人资料可见范围；不同内容项目容易误用角色和风格，迁移与权限边界不清晰。

### C. 使用项目 `.ip-pic/`、不可变版本和计划确认协议

角色、风格和导演预设分别版本化。Agent 先生成计划，用户确认后由确定性运行时应用；安装目录保持不可变。

## 决策

选择 C。

自然语言理解属于宿主 Agent；合法性、标准化、路径安全、版本分配、激活、回退和编译解析属于 Skill 的确定性代码。私人资料只写用户明确置于作用域内的项目 `.ip-pic/`。

## 结果

- 用户可以用自然语言持续修改，并保留全部历史版本。
- Skill 更新不会覆盖私人配置。
- 同一项目内的角色、风格和导演设置可审计、可回退。
- 写入前必须有可展示的计划和用户明确确认。
- 项目间共享不自动发生；需要用户日后明确复制或导出。
- 公共发布扫描可以继续证明仓库不包含用户身份、私人素材、凭证和私有路径。
- 运行时和测试代码增加，但这是把文档卖点变成真实产品能力所必需。

## 不可变约束

- 不允许覆盖已有版本；
- 不允许 `.ip-pic` 或资产文件为符号链接；
- 不允许项目外参考路径；
- 不允许个人风格携带身份、场景、画幅、交付或后端控制字段；
- 不允许未确认计划写入活动状态；
- 不修改原版 Image Factory、全局 Skill 或公开安装目录。
